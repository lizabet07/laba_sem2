## 2. Описание реализованных типов и контейнеров

### 2.1 Аннотации типов

Все классы из предыдущих лабораторных работ (BankAccount, SavingsAccount, CreditAccount, PremiumAccount) дополнены аннотациями типов. Аннотированы следующие элементы:

- **Параметры конструктора** — каждый параметр имеет указание типа
- **Возвращаемые значения методов** — каждый метод явно указывает тип возвращаемого значения
- **Атрибуты в __init__** — все внутренние переменные имеют аннотации типов
- **Свойства (property)** — геттеры аннотированы с указанием возвращаемого типа

Преимущества аннотаций типов:
- IDE подсказывает типы параметров при вызове методов
- Статический анализатор (mypy) может проверить корректность типов
- Код становится самодокументируемым
- Упрощается рефакторинг и поддержка кода

### 2.2 Generic-класс TypedCollection

TypedCollection — это обобщённая коллекция, которая может хранить элементы любого типа (или типа с ограничением). Она повторяет интерфейс коллекции из лабораторной работы №2, но теперь тип элементов известен на уровне статического анализа.

#### TypeVar и их назначение

| TypeVar | Ограничение | Назначение |
|---------|-------------|------------|
| T | нет (любой тип) | Базовый тип элементов коллекции |
| R | нет (любой тип) | Тип результата в методе map (может отличаться от T) |
| D | Displayable | Только объекты с методом display() |
| S | Scorable | Только объекты с методом score() |

#### Методы коллекции

**__init__()** — Создаёт пустую коллекцию. Возвращает None.

**add(item: T)** — Добавляет элемент в коллекцию. Возвращает self для поддержки цепочек вызовов.

**remove(item: T)** — Удаляет элемент из коллекции. Возвращает self для поддержки цепочек вызовов.

**get_all()** — Возвращает копию всех элементов в виде списка. Тип возврата — list[T].

**sort_by(key_func, reverse)** — Сортирует коллекцию по переданной функции-ключу. Параметр reverse позволяет сортировать в обратном порядке. Возвращает self для цепочек.

**filter_by(predicate)** — Фильтрует коллекцию по предикату. Возвращает новую коллекцию TypedCollection[T] с отфильтрованными элементами. Исходная коллекция не изменяется.

**find(predicate)** — Находит первый элемент, удовлетворяющий условию. Возвращает Optional[T] — элемент или None, если ничего не найдено.

**filter(predicate)** — Фильтрует коллекцию по предикату. Возвращает список list[T] отфильтрованных элементов. Отличие от filter_by в типе возвращаемого значения.

**map(transform)** — Применяет функцию преобразования к каждому элементу. Возвращает список list[R], где R — тип результата преобразования. Ключевая особенность: тип результата может отличаться от типа элементов коллекции.

**__len__()** — Возвращает количество элементов в коллекции (тип int).

**__getitem__(index)** — Предоставляет доступ к элементу по индексу. Возвращает элемент типа T.

**__iter__()** — Возвращает итератор для перебора элементов в цикле.

#### Особенность метода map

Метод map использует второй TypeVar с именем R, что позволяет изменять тип элементов при преобразовании. Это демонстрирует мощь generic-типов:

- Из TypedCollection[BankAccount] можно получить list[str] (имена владельцев)
- Из TypedCollection[BankAccount] можно получить list[float] (балансы)
- Из TypedCollection[BankAccount] можно получить list[tuple] (составные данные)

Без второго TypeVar пришлось бы ограничиваться только исходным типом T.

### 2.3 Протоколы (структурная типизация)

Для демонстрации концепции структурной типизации созданы два протокола.

**Протокол Displayable** требует наличия метода display(), который возвращает строку. Этот метод должен возвращать строковое представление объекта для отображения пользователю.

**Протокол Scorable** требует наличия метода score(), который возвращает число с плавающей точкой. Этот метод должен возвращать числовую оценку объекта для сравнений и вычислений.

Суть структурной типизации (утиная типизация на уровне типов):
- Объект соответствует протоколу, если у него есть все необходимые методы
- Явное наследование от протокола не требуется
- Это позволяет разным классам из разных иерархий работать в одном контексте

#### Классы, соответствующие протоколам

Все классы банковских счетов (BankAccount, SavingsAccount, CreditAccount, PremiumAccount) соответствуют обоим протоколам без явного наследования:

- **BankAccount** имеет методы display() и score(), унаследованные всеми производными классами
- **SavingsAccount** наследует эти методы, переопределяя display() для добавления информации о накопительном счёте
- **CreditAccount** наследует эти методы, переопределяя display() для добавления информации о кредитном лимите
- **PremiumAccount** наследует эти методы, переопределяя display() для добавления информации о кэшбэке

Метод score() во всех классах возвращает баланс счёта, что позволяет использовать его для численных операций.

Важно отметить, что ни один из этих классов не наследует Displayable или Scorable явно. Они соответствуют протоколам только потому, что имеют методы display() и score() с правильными сигнатурами.

**Описание:** Демонстрация использования аннотаций типов в классах. Показывает, что конструктор принимает типизированные параметры, а методы возвращают значения ожидаемых типов.

**Что демонстрируется:**

### Сценарий 2: Generic-коллекция

**Описание:** Демонстрация работы TypedCollection с разными типами данных.

**Что демонстрируется:**
- TypedCollection[str] — коллекция строк
- TypedCollection[int] — коллекция чисел
- TypedCollection[BankAccount] — коллекция банковских счетов
- Валидация типов на уровне статического анализа

**Исходные данные:**
- Три строки: "Первый", "Второй", "Третий"
- Пять чисел: 1, 2, 3, 4, 5
- Пять банковских счетов с разными балансами

**Результат:**
- Коллекция строк содержит 3 элемента
- Коллекция чисел содержит 5 элементов, сумма равна 15
- Коллекция счетов содержит 5 счетов с правильными балансами
- Попытка добавить число в коллекцию строк вызывает ошибку типа при статическом анализе

**Вывод:** TypedCollection сохраняет информацию о типе элементов. Ошибки несоответствия типов обнаруживаются на этапе статического анализа.

### Сценарий 3: Методы find, filter, map

**Описание:** Демонстрация работы функциональных методов коллекции, особенно map с изменением типа.

**Что демонстрируется:**
- find() — поиск элемента с возвратом Optional[T]
- filter() — фильтрация с возвратом list[T]
- map() — преобразование с изменением типа (ключевой момент для оценки 4)

**Исходные данные:** Коллекция из 8 банковских счетов с разными балансами и статусами

**Результат find():**
- Поиск счета с балансом больше 100000 рублей: найден счёт Петровой Марии с балансом 120000 рублей
- Поиск несуществующего владельца: возвращён None

**Результат filter():**
- Активные счета: 6 счетов
- Счета с балансом больше 100000 рублей: 3 счета

**Результат map() с изменением типа:**
- Преобразование BankAccount → str: получен список имён владельцев (тип list[str])
- Преобразование BankAccount → float: получен список балансов (тип list[float])
- Преобразование BankAccount → tuple: получен список кортежей (имя, баланс, статус) (тип list[tuple])

**Вывод:** Метод map может менять тип элементов. Был TypedCollection[BankAccount], стали list[str], list[float], list[tuple]. Это достигается с помощью второго TypeVar R.

### Сценарий 4: Протокол Displayable

**Описание:** Демонстрация структурной типизации через протокол Displayable.

**Что демонстрируется:**
- Коллекция TypedCollection[D] принимает только объекты с методом display()
- Объекты разных типов соответствуют протоколу без явного наследования
- Безопасный вызов метода display() для всех элементов

**Исходные данные:**
- BankAccount (Иванов Иван)
- SavingsAccount (Петрова Мария)
- PremiumAccount (Кузнецова Елена)

**Результат:**
- Все три объекта успешно добавлены в коллекцию TypedCollection[D]
- Метод display() вызван для каждого объекта
- Разные типы дают разные строковые представления:
  - BankAccount: номер, владелец, баланс, статус
  - SavingsAccount: добавляется пометка "накопительный"
  - PremiumAccount: добавляется информация о кэшбэке

**Вывод:** Протоколы обеспечивают структурную типизацию. Объект соответствует протоколу, если у него есть нужные методы, даже без явного наследования. Это позволяет использовать разнородные объекты в едином контексте.

### Сценарий 5: Протокол Scorable

**Описание:** Демонстрация работы с протоколом Scorable.

**Что демонстрируется:**
- Коллекция TypedCollection[S] принимает только объекты с методом score()
- Использование метода score() для численных операций
- Фильтрация и поиск на основе числовых значений

**Исходные данные:** Коллекция из 6 банковских счетов

**Результат:**
- Все счета имеют метод score(), возвращающий баланс
- Оценки счетов: от 0 рублей (закрытый счёт) до 250000 рублей
- Фильтрация по score > 100000: найдено 2 счета
- Максимальный score: 250000 рублей у Кузнецовой Елены

**Вывод:** Протокол Scorable позволяет унифицированно работать с числовыми характеристиками разных объектов. Метод score может быть переопределён в производных классах для изменения логики расчёта оценки.

### Сценарий 6: Разные ограничения для одного класса

**Описание:** Демонстрация того, что один и тот же класс TypedCollection может работать с разными ограничениями.

**Что демонстрируется:**
- TypedCollection[T] — без ограничений (любые типы)
- TypedCollection[D] — только Displayable
- TypedCollection[S] — только Scorable

**Исходные данные:**
- Разные типы объектов: BankAccount, числа, строки, списки

**Результат:**
- Коллекция без ограничений: может хранить любые типы (счета, числа, строки, списки)
- Коллекция Displayable: хранит только объекты с методом display() (BankAccount, SavingsAccount, PremiumAccount)
- Коллекция Scorable: хранит только объекты с методом score() (BankAccount, CreditAccount, SavingsAccount)

**Вывод:** TypedCollection — гибкий generic-класс, который может работать с разными типами и ограничениями. Один и тот же класс используется для разных целей в зависимости от переданного TypeVar.

### Сценарий 7: Цепочки вызовов

**Описание:** Демонстрация fluent-интерфейса — цепочек вызовов методов.

**Что демонстрируется:**
- filter_by → sort_by → map (полная цепочка)
- filter_by → map (изменение типа)
- filter_by → find (поиск)

**Исходные данные:** Коллекция из 8 банковских счетов

**Результат цепочки filter_by → sort_by → map:**
- Фильтрация: оставляем только активные счета
- Сортировка: по убыванию баланса
- Преобразование: в строки формата "владелец: баланс₽"
- Результат: Новикова Ольга: 600000₽, Кузнецова Елена: 250000₽, Петрова Мария: 120000₽ и т.д.

**Результат цепочки filter_by → map:**
- Фильтрация: счета с балансом > 100000₽
- Преобразование: в строки с звёздочками "★ владелец ★"
- Результат: ★ Петрова Мария ★, ★ Кузнецова Елена ★, ★ Новикова Ольга ★

**Результат цепочки filter_by → find:**
- Фильтрация: активные счета
- Поиск: счёт с балансом > 200000₽
- Результат: найден счёт Кузнецовой Елены

**Вывод:** Методы, возвращающие self или новую коллекцию, позволяют строить цепочки вызовов. Важно использовать filter_by (возвращает TypedCollection) вместо filter (возвращает list), так как только TypedCollection имеет методы для продолжения цепочки.

### 4.3 Метод map с изменением типа

Ключевое достижение для оценки 4 — метод map, использующий второй TypeVar R. Это позволяет:
- Преобразовывать TypedCollection[BankAccount] в list[str] (имена)
- Преобразовывать TypedCollection[BankAccount] в list[float] (балансы)
- Преобразовывать TypedCollection[BankAccount] в list[tuple] (составные данные)

### 4.4 Структурная типизация через Protocol

Созданы протоколы Displayable и Scorable, которые:
- Определяют контракт через наличие методов display() и score()
- Не требуют явного наследования от протокола
- Позволяют использовать объекты разных классов в едином контексте

### 4.5 TypeVar с ограничением bound

TypeVar D и S имеют ограничения bound=Displayable и bound=Scorable соответственно. Это:
- Гарантирует, что в коллекцию можно добавить только объекты с нужными методами
- Позволяет IDE знать, что у элементов коллекции есть методы display() и score()
- Обеспечивает типобезопасность на уровне статического анализа

### 4.6 Единый класс с разными ограничениями

Продемонстрировано, что один и тот же класс TypedCollection может работать с разными TypeVar:
- TypedCollection[T] — для любых типов
- TypedCollection[D] — только для Displayable
- TypedCollection[S] — только для Scorable

### 4.7 Практическая польза типизации

Типизация помогает:
- Читать и понимать код — по сигнатуре метода видно, что он принимает и что возвращает
- Писать правильный код — IDE подсвечивает ошибки до выполнения программы
- Рефакторить — изменение типа в одном месте автоматически проверяется во всех местах использования
- Документировать — аннотации служат документацией, которая не устаревает
